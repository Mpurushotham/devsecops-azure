Three ideas the design rests on

Everything else is consequence. If you read nothing further, read these.

No long-lived credentials exist

CI, Azure DevOps and pods all federate into Entra ID over OIDC. There is no registry password, no service principal secret, no database password. Each federated credential is pinned to a single claim — repository + environment, or namespace + service account — so a compromised staging pod cannot obtain a production token. The claim is the boundary.

The pipeline never deploys

CI builds and signs an image, then commits a digest change or opens a pull request. Argo CD reconciles. A compromised pipeline can propose a change, not make one — and rollback is git revert, the same mechanism as the forward path, so it is exercised constantly instead of being an untested emergency procedure.

Guardrails are enforced three times

The Helm chart sets the secure values; rendered output is asserted against 17 contract checks in CI; Kyverno and Pod Security reject violations at admission. A team supplies an image and a few values. Being non-root with dropped capabilities, resource requests, a disruption budget and a network policy is not something they can forget.

How a change reaches production

The dotted edge is the one that matters: CI writes to git, never to the cluster.

Network segmentation

Four subnets by trust level, deny-by-default at every boundary. The data subnet also denies outbound internet: a private endpoint never legitimately originates a connection, which turns a stolen credential from an exfiltration path into a dead end.

Identity, end to end

Three federation relationships replace three stored credentials. Verified on the running pod: the webhook injected the client ID, tenant ID and a projected token path. No Kubernetes Secret was created.

Two controls proved themselves by refusing work

Which is the only way to know a control is live rather than declared. Pod Security restricted rejected a debug pod that omitted capability drops. The default-deny NetworkPolicy blocked an in-cluster probe — the application was reachable only through kubectl port-forward, because the chart's policy admits ingress from the ingress controller and nothing else.

What deploying for real found

Nine defects in three waves. Each layer catches a class the previous one structurally cannot — and terraform validate had been passing cleanly throughout.

Wave 1 — found by plan, the dependency graph

Invalid count argument

Eleven resources across four modules gated count on an id computed by another resource in the same apply. Terraform cannot evaluate that at plan time. It affected every environment equally — all validated cleanly, all would have failed on first use.

Gate on plain booleans that are known before the graph is walked.

Wave 2 — found by apply, what Azure actually accepts

K8sVersionNotSupported

1.31 has left mainstream support and is now LTS-only.

Track a version with mainstream support; 1.34.

SubnetsHaveNoServiceEndpointsConfigured

A subnet must carry a service endpoint before it can be named in a PaaS network ACL. The ACL is accepted by the schema and rejected by the API.

Service endpoints on the cluster subnets.

ip_rules must start with IPV4 address

Azure storage ACLs reject a /32 suffix; a single address must be bare.

Normalise at the module boundary, so callers keep passing ordinary CIDRs.

The VM size is not allowed in your subscription

Standard_B2s (v1) is simply not offered on this subscription.

Standard_B2s_v2, verified against the SKU list first.

KeyBasedAuthenticationNotPermitted

Shared keys are disabled on the storage account — correctly — but the provider's own data-plane polling was still trying to use one.

storage_use_azuread = true.

403 ForbiddenByRbac

Entra RBAC is eventually consistent. A secret write in the same apply raced the role assignment and failed on a permission the operator demonstrably held.

Gate the vault id output behind a propagation wait, so every consumer inherits the ordering.

Wave 3 — found by running a workload on it

FailedScheduling: didn't match node affinity

The chart selects workload-type: application. A single-pool cluster had no node carrying that label.

The platform labels the system pool when there is no app pool — so one chart works in every topology, rather than each environment overriding it.

401 Unauthorized from the registry token endpoint

The kubelet identity had no AcrPull. The cluster module cannot grant it: the registry is created after the cluster, so referencing it there is a cycle.

The assignment belongs to the module that owns the registry.

Insufficient cpu — 2 pods Pending

AKS platform components alone request roughly 1.8 of 2 vCPU on one node. Two nodes are needed before any workload fits.

The autoscaler resolved it, 1 → 2 nodes. Worth knowing before sizing a small cluster.

Standing cost

A budget alert at €50 fires at 50%, 80% and forecast 100% — but Azure budgets alert, they do not enforce. Nothing stops this environment spending until it is destroyed.

Teardown is a single command and is the intended end state: make destroy ENV=sandbox.

What this deliberately does not claim

Only sandbox has been applied. The dev, staging and production shapes are planned but unapplied, and their costs are estimates. Disaster recovery is single-region with geo-redundant backups; a cross-region plan is the next piece of work. The reference application demonstrates the platform contract and has no business logic worth the name.
